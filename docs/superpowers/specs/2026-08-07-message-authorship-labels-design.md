# Message Authorship Labels — Design Spec

**Date:** 2026-08-07
**Status:** draft, awaiting owner review
**Relates to:** `docs/superpowers/specs/2026-07-13-conversation-introspection-design.md` (capture-then-interpret; messages/content_blocks as derived interpretation cache); `docs/superpowers/specs/2026-08-04-conversation-view-refinements-design.md` (reader surfaces this feature relabels); `docs/dev/README.md` (schema-version + reparse workflow)

## 1. Overview and motivation

The reader labels every `user`-role record **YOU** (dawn accent). That is accurate for the
records the owner actually typed and wrong for everything else the harness delivers in the
user role: tool results, skill-content injections, task notifications, system reminders,
slash-command expansions, subagent dispatch prompts, SDK/automation prompts, interruption
markers, compaction summaries. Of the ~20,150 user-type rows the interpretation layer
serves (2026-08-07; the raw table holds ~780 more on superseded generations), only ~490
are human-authored — ~430 verified (`promptSource` typed/queued) plus ~60 inferred
pre-2.1.168 records. The rest currently wear the owner's label.

Goal, in the owner's words: labels with **both accuracy and precision** — YOU never lies,
and non-human records say what they actually are, as specifically as the data allows.

Approved structure (owner, 2026-08-07):

- **Core voice + qualifier** labels, extending the established `SYSTEM (YOU)`
  materially-X-sourced-from-Y pattern. A few primary voices (YOU / CLAUDE / SYSTEM) keep the
  accent system calm; a qualifier carries the precision — e.g. `SYSTEM (SKILL: brainstorming)`,
  `CLAUDE (DISPATCH)`.
- **Three-state view control** replacing the two-state conversation-only toggle:
  `chat · chat+harness · all`, reader default `chat`.
- **Plain YOU for verified and inferred human records alike**; the classification verdict and
  its basis are shown per-record in the raw inspector, not as a two-tier eyebrow.
- **Approach A — parse-time classification** stored on `messages`, regenerated by reparse
  (owner chose A over read-time and client-side alternatives).

## 3. Classification spec

### 3.1 Contract

A pure, **total, never-raising** classifier assigns every message record:

- `authorship_kind` — one enumerated kind (below). Total across record types: assistant
  records classify `claude`, system records `system`, attachments `attachment_queued_human`
  (block-bearing rescued queued prompt) or `attachment_furniture` (zero-block). The
  reader's current `voiceOf()` special-casing moves into the classifier: one source of truth.
- `authorship_basis` — `verified` (an explicit harness field decided) or `heuristic`
  (content-shape/elimination decided), plus the deciding rule, serialized as a short string
  for the inspector (e.g. `verified — promptSource: typed`,
  `heuristic — main transcript, no harness markers`).
- `authorship_detail` — nullable specifics: skill name, tool name, command name,
  reminder/caveat discriminant.

### 3.2 Decision tree for `user`-role records — first match wins

| # | Rule | kind | detail | basis |
|---|---|---|---|---|
| 1 | `isCompactSummary` | `compact_summary` | — | verified |
| 2 | tool_result block present, or `toolUseResult` echo (the block is authoritative — the echo never occurs alone in production) | `tool_result` | tool name via the interpreter's per-transcript tool_use map (§4); inspector-only | verified |
| 3 | `sourceToolUseID` resolves to a `Skill` tool_use | `skill_injection` | the tool_use `input.skill` value | verified |
| 4 | `sourceToolUseID` resolves to any other tool_use (or dangles) | `tool_injection` | joined tool name, null if dangling | verified |
| 5 | `origin.kind = task-notification` or `promptSource = system` | `task_notification` | — | verified |
| 6 | `origin.kind = coordinator` | `coordinator` | — | verified |
| 7 | `promptSource = typed` / `queued` | `human_typed` / `human_queued` | — | verified |
| 8 | `promptSource = sdk` | `sdk_automation` | — | verified |
| 9 | string content starts `<command-name>` | `command_expansion` | command name from the tag | heuristic |
| 10 | string content starts `<local-command-stdout>` | `command_output` | — | heuristic |
| 11 | `isMeta` true (remaining) | `harness_meta` | `reminder` / `caveat` by prefix, else null | heuristic |
| 12 | text content (string, or a text block) starting `[Request interrupted by user` | `interrupt_marker` | `tool` for the "for tool use" variant, else null | heuristic |
| 13 | `isSidechain` true OR transcript kind `subagent` (remaining) — openers and mid-run dispatcher messages | `dispatch` | — | verified |
| 14 | `promptSource` present but not in {typed, queued, system, sdk}, OR `origin.kind` present but not in {human, task-notification, coordinator} | `unclassified` | the unrecognized value | verified |
| 15 | remaining main-transcript records with text content (string, or array containing text/image blocks), no `promptSource`, no `origin`, CLI version **< 2.1.168** (the pre-`promptSource` era) | `human_inferred` | — | heuristic |
| 16 | anything else | `unclassified` | — | heuristic |

Rule 12 covers both the string-content and single-text-block-array marker forms across all
CLI versions and both transcript kinds; it precedes the sidechain rule so sidechain
interrupts don't mislabel as `dispatch`. It exists because the marker text is
harness-authored boilerplate for a human *action* — labeling it YOU would put words in
the owner's mouth (census finding, §2).

Rule 15 is a **positive inference, not a fallback**: `promptSource` ships with every
human prompt from CLI 2.1.168 onward (verified — the 2026-08-07 census found the post-era
no-source main-text population is exactly the interrupt markers, zero exceptions), so a
post-era record lacking authorship fields is *evidence of harness origin*, and it falls
to rule 16, not to YOU. Rules 13 and 15 both use `isSidechain OR transcript-kind`, the
belt-and-suspenders pair, so a hand-edited record that lost its `isSidechain` flag (a
tolerance the pretty-jsonl spec grants) still cannot cross from dispatch to human.

Properties (tested, §8): **YOU-producing kinds (`human_*`) are reachable only through
rules 7 and 15**, every harness-shaped record drains through 1–14 first, and — because
rule 15 is version-gated — the `unclassified` alarm (rules 14/16) is genuinely reachable
by future drift: a new `promptSource` value, a new `origin.kind`, or a post-era record
with no fields at all each land on the alarm, never on YOU. Production floor today: 0.

### 3.3 Kind → eyebrow label / accent map (client)

| kind | eyebrow | accent |
|---|---|---|
| `human_typed`, `human_queued`, `human_inferred` | YOU | dawn |
| `claude` | CLAUDE | dragonfly |
| `dispatch` | CLAUDE (DISPATCH) | dragonfly |
| `coordinator` | CLAUDE (COORDINATOR) | dragonfly |
| `tool_result` | SYSTEM (TOOL RESULT) | mist |
| `skill_injection` | SYSTEM (SKILL: <name>) — plugin prefix stripped for display (`superpowers:brainstorming` → `brainstorming`); full value stays in `authorship_detail` | mist |
| `tool_injection` | SYSTEM (INJECTED: <tool>); SYSTEM (INJECTED) when detail is null (dangling join) | mist |
| `task_notification` | SYSTEM (TASK NOTIFICATION) | mist |
| `sdk_automation` | SYSTEM (AUTOMATION) | mist |
| `command_expansion` | SYSTEM (COMMAND: /<name>) | mist |
| `command_output` | SYSTEM (COMMAND OUTPUT) | mist |
| `harness_meta` | SYSTEM (REMINDER) / SYSTEM (CAVEAT) / SYSTEM (META) — deliberately also the home for non-string `isMeta` payloads (e.g. the 8 base64 document injections after a PDF Read), detail null there | mist |
| `interrupt_marker` | SYSTEM (INTERRUPT) | mist |
| `compact_summary` | SYSTEM (COMPACTION) | mist |
| `unclassified` | SYSTEM (UNCLASSIFIED) | mist |
| `system` | SYSTEM, with the record's `subtype` as qualifier when present — SYSTEM (TURN DURATION), SYSTEM (API ERROR), … (`authorship_detail` = subtype; free precision, §1 goal) | mist |
| `attachment_queued_human` | SYSTEM (YOU) | dawn |
| `attachment_furniture` | SYSTEM | mist |

Qualifier names (skill/command/tool) render lowercase to keep eyebrows quiet. Dawn is
reserved for human-authored content — only `human_*` and `attachment_queued_human` may
take it. Exact label wording is tunable at implementation review without spec revision;
the kind enumeration is the contract.

## 4. Storage & schema generation

- Alembic migration: three nullable columns on `messages` — `authorship_kind`,
  `authorship_basis`, `authorship_detail` — plus `ix_messages_transcript_id ON
  messages(transcript_id, id)`. No index on `authorship_kind`: every view predicate is
  transcript-scoped, and `messages` currently has *no* transcript index at all (verified —
  the composite index serves both the new predicates and existing per-transcript reads).
- Classifier location: beside the schema registry as a **pure function** — the schema
  package's DB-free tenet (`v1.py` module docstring) is binding. All context arrives
  injected: the transcript kind, and a per-transcript `{tool_use_id → tool name/input}`
  map the interpreter builds **in memory before classifying that transcript's records**.
  The map makes the rules-2/4 join free (no per-record query — without it, reparse would
  scan 54k content_blocks per tool_result, ~10⁹ row visits) and order-independent (18
  production tool_results precede their tool_use in file order; a sequential DB lookup
  would misclassify what a whole-transcript map cannot).
- Generation bump: `introspect-schema/7`, DIFF_NOTES entry = interpretation change (no new
  declared envelope fields), following the /3 precedent. One reparse backfills all records.
- A dangling tool_use reference degrades (rule 4 null detail; rule 2 null detail) — never
  an error.
- **Deploy ordering is part of the spec:** migrate → reparse → serve. Between migration
  and reparse the columns are NULL; the §5 predicates are NULL-tolerant so an
  un-backfilled archive degrades to today's behavior, never to an empty reader (the cron
  importer runs continuously, so the window is real).
- Reparse reporting: the run summary prints the authorship census (count by kind) and flags
  `unclassified > 0`.

## 5. API & filtering

- `MessageOut` gains `authorship_kind`, `authorship_basis`, `authorship_detail` verbatim.
- The boolean `chat_only` parameter (messages endpoint + seed logic) is **deleted** —
  zero-legacy, pre-release — replaced by `view: chat | chat-harness | all` (server default
  `all`; the reader always passes its state).
  - `chat`: `authorship_kind IN (human_typed, human_queued, human_inferred, claude,
    attachment_queued_human, interrupt_marker, dispatch, coordinator)`, with the existing
    prose-visibility predicate layered on top (thinking-only / tool-only / empty CLAUDE
    turns still collapse). Owner decision (2026-08-07): interrupt markers and
    queued-delivery human content stay visible in dialogue view — they are part of the
    conversation's story even when the words are harness-delivered. `dispatch` and
    `coordinator` are included because they are CLAUDE-voice by §3.3 — without them a
    subagent transcript in `chat` view would render 5,000+ answers with zero prompts.
  - `chat-harness`: everything except `tool_result` (harness prose shows, honestly
    labeled), same prose-visibility layer. Row-set note: this state is row-identical to
    today's toggle-on view — its value is honest labels, not new rows; the genuinely new
    row-set is `chat` (~7.7× fewer rows than today's default).
  - `all`: everything.
  - **NULL tolerance (deploy window, §4):** all predicates treat a NULL `authorship_kind`
    by falling back to the current type-based rule (`type IN (user, assistant,
    attachment)` + prose-visibility), so pre-reparse rows render as they do today. The
    `chat-harness` exclusion is written NULL-safe (`authorship_kind IS NULL OR
    authorship_kind <> 'tool_result'`).
- `web/src/lib/chatOnly.ts` becomes the three-valued mirror of the same predicate (renamed
  accordingly), preserving the invariant that reader-visible rows and inspector prev/next
  navigation can never drift.

## 6. UI

- `MessageTurn.voiceOf()` is replaced by the §3.3 map over `authorship_kind`.
- `ChatOnlyToggle` becomes a three-state control — `chat · chat+harness · all` — reader
  default `chat`. **View state stays localStorage-sticky** (`introspect.view.v1`),
  replacing today's `introspect.chatOnly.v1` boolean key (deleted, no alias, stale keys
  ignored — zero-legacy). There is no URL param and never was one — the earlier draft's
  "old `chatOnly` param" premise was wrong; the one-owner-per-page hook model in
  `chatOnly.ts` carries over to the three-state hook. The around-404 recovery notice
  ("show all message types") targets `all` — the only view guaranteed to contain a
  `tool_result` deeplink.
- **Per-view block rendering:** in `chat` and `chat-harness`, `tool_result` blocks are
  hidden and a `tool_use` block renders **only** when it resolves to a subagent dispatch
  (`SubagentChip` — the reader's sole doorway into subagent transcripts, which the old
  boolean filter would have deleted from the default view); ordinary tool calls stay
  hidden. `all` renders every block.
- The raw-record inspector gains one classification line rendered from the three fields:
  `authorship: skill_injection (verified — sourceToolUseID → Skill: brainstorming)`.
- No other surfaces change: search hits and the session list do not label speakers today
  and remain out of scope (§9).

## 7. Error handling

- The classifier is total and never raises; `unclassified` is the floor.
- `unclassified` doubles as the drift alarm (anomaly-floor philosophy): current archive
  target is 0; a future CLI introducing a new user-record shape raises the count visibly in
  the reparse census rather than mislabeling anything YOU.
- Dangling tool joins degrade to null detail, never block classification.
- Old records never block: rules 9–13 require no fields that postdate them.

## 8. Testing & validation

- **TDD per rule:** fixture records copied from real archive shapes — at least one per §2
  census cluster, including both interrupt-marker forms, a *sidechain* interrupt, and one
  pre-era + one post-era fieldless record — asserting kind, basis, and detail. Rule-order
  property tests: every harness-shaped fixture classifies before rule 15; `human_*`
  reachable only via rules 7/15; a post-era fieldless record and an unrecognized
  `promptSource`/`origin.kind` value each reach `unclassified`, never YOU.
- **Pre-UI census gate:** before any UI work, run the classifier across the full archive
  (subagent-executed), **over the interpreted `messages` table** (what the classifier
  actually serves — ~779 raw rows sit on superseded generations and are out of scope),
  report census-by-kind, and sample-read every cluster against expectation. A cluster
  that contradicts a rule updates this spec before the room changes.
- **Three-way filter tests:** server predicate and the client mirror agree on the same
  fixture transcript for all three views, including the NULL-`authorship_kind` fallback
  rows (§5).
- **Post-UI walk:** production walk covering a subagent transcript (DISPATCH opener), a
  skill expansion, a task notification, a tool-result-dense stretch, and the conversation
  that designed this feature.

## 9. Non-goals

- **No MCP server.** Subagents use read-only SQLite directly; the FastAPI endpoints serve
  the web reader. An introspect-MCP (typed archive access for other Claude sessions) is a
  separate backlog item, deliberately uncoupled (owner, 2026-08-07).
- **No search-hit or session-list speaker labels** — those surfaces don't label today.
- **No subagent-tier bylines on CLAUDE turns** (which minion model typed a sidechain turn);
  SubagentChip context already identifies subagent transcripts, and tier attribution is a
  separate concern.
- **No re-litigation of `SYSTEM (YOU)`** — the rescued queued-prompt attachment behavior is
  unchanged, now expressed through the classifier.

## 10. Owner decisions log (2026-08-07)

1. Label structure: core voice + qualifier (over first-class-per-kind and minimal-generic).
2. View control: three-state toggle `chat · chat+harness · all`, default `chat`.
3. Verified vs inferred human: plain YOU for both; basis lives in the inspector.
4. Architecture: Approach A — parse-time classification stored on `messages`, reparse
   regenerates (over read-time API classification and client-side classification).
5. Subagent-first execution where possible (standing SDD authorization applies).
6. *Helm ruling (Claude), owner-amended same day:* interruption markers
   (`[Request interrupted by user]`) are harness-authored text for a human action —
   classified `interrupt_marker` / SYSTEM (INTERRUPT), mist. Rationale: YOU must mean
   "these words came from the human." Owner review kept the classification but amended
   visibility: interrupts remain visible in `chat` view (they mark the owner's own act),
   as does queued-delivery human content (`human_queued`, `attachment_queued_human`).
7. *Helm rulings from the verified fresh-eyes review (Claude, batched for owner review;
   every adopted finding was re-verified against the live archive or code before
   adoption, per the owner's Opus-caution directive — including correcting the review's
   own miscount of the pre-era human population, 68 not 8):* (a) rule 15 inverted to a
   version-gated positive inference so the `unclassified` drift alarm is genuinely
   reachable; (b) `dispatch`/`coordinator` included in `chat` view; (c) subagent-dispatch
   chips survive in `chat`/`chat-harness` (sole subagent navigation); (d) view state
   stays localStorage-sticky — the earlier URL-param framing rested on a wrong premise;
   (e) system-record `subtype` carried as free label precision; (f) per-transcript
   in-memory tool_use map + `(transcript_id, id)` index instead of per-record joins and
   an `authorship_kind` index.
